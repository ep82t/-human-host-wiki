# 日本税制・社会保険法令 自動収集／Google Drive保存システム

日本の税制・社会保険・労働保険に関する法令データを、政府公式の
**e-Gov法令検索（法令API Version 2）** から自動取得し、
Google Drive の専用フォルダへ整理して保存する Google Apps Script システムです。

法令が改正されると、1日1回の自動チェックで **変更された法令だけ** が更新されます。

---

## 🚀 はじめての方へ

**[はじめかた.md](はじめかた.md)** に、クリック手順だけの最短ガイドがあります。
所要時間は約15分、貼り付けるファイルは2つだけです。

このREADMEは全機能の詳細を説明したものです。まず動かしたい方は上のガイドをご覧ください。

## ⚠️ 使い始める前に必ず読んでください

このコードを書いた開発環境では、**ネットワーク制限により `laws.e-gov.go.jp` へ
アクセスできませんでした**。そのため、公式OpenAPI仕様書を直接確認できていません。

ただし、**実際に e-Gov 法令API v2 を呼び出している公開パッケージのソースコードを
取得して照合済み**です（npm: `@gonuts555/e-gov-mcp`, `law-mcp-server`）。
主要なパス・パラメータ名・レスポンス構造は、この照合で一致を確認しています。
詳細は [`docs/API_SPEC_NOTES.md`](docs/API_SPEC_NOTES.md) の「2.5」をご覧ください。

そこで、この問題に対処するための仕組みを組み込んでいます。

1. APIのパス・パラメータ名は **`src/02_api_spec.gs` の1か所だけ** に集約しています。
   仕様が違っていた場合、修正するのはこのファイルの値だけです。
2. **`verifyApiSpec()`** を実行すると、公式のOpenAPI仕様を取得して
   設定値と自動で突き合わせ、差異をレポートします。
3. レスポンスの項目名は1つに決め打ちせず、複数の候補を順に探すため、
   名前が多少違っても止まりません。

**`setup()` の前に、必ず `verifyApiSpec()` を実行してください。**
詳しくは [`docs/API_SPEC_NOTES.md`](docs/API_SPEC_NOTES.md) を参照してください。

なお、**法令データの解析・変換・保存・差分検出のロジックは実際に実行して検証済み**です
（テスト28件すべて成功）。検証できていないのは、e-Gov APIとの通信部分だけです。

## 1. このシステムで何ができるか

| できること | 説明 |
| --- | --- |
| 法令の自動取得 | e-Gov法令API v2 から45件の法令を自動取得します |
| 原本の保存 | e-Govの正式データを**一切加工せず**保存します（XML優先、無ければJSON） |
| Markdown生成 | 原本から機械的に変換した、人間とAIが読みやすい形式を生成します |
| 構造化JSON生成 | 条・項・号に分解し、将来のRAG／AI検索に使える形にします |
| 改正の自動検出 | SHA-256ハッシュで比較し、変わった法令だけを更新します |
| 履歴の保存 | 改正前のデータを削除せず `99_履歴` へ退避します |
| 廃止法令の管理 | 削除せず `status` を `repealed` などに変更して残します |
| 自動実行 | 1日1回、Google側で自動実行されます（PCの起動は不要） |

### 取得する法令（45件）

- **税制（21件）**：国税通則法／所得税法／法人税法／消費税法／相続税法／租税特別措置法／地方税法
  （それぞれ 法律・施行令・施行規則）
- **社会保険（15件）**：健康保険法／厚生年金保険法／国民年金法／国民健康保険法／介護保険法
  （それぞれ 法律・施行令・施行規則）
- **労働保険（9件）**：雇用保険法／労働者災害補償保険法／労働保険の保険料の徴収等に関する法律
  （それぞれ 法律・施行令・施行規則）

法令の追加・削除は `src/01_laws_config.gs` を編集するだけで行えます（→ 第11章）。

### 将来の拡張について

国税庁の通達・質疑応答事例、厚生労働省・日本年金機構の資料などは、
**法令本文とは絶対に混在させず**、`05_国税庁資料` `06_厚生労働省資料`
`07_日本年金機構資料` として別カテゴリで追加できる構造になっています
（`src/00_config.gs` の `FUTURE_CATEGORIES` を参照）。

## 2. Google Apps Script プロジェクトの作成方法

1. ブラウザで <https://script.google.com/> を開きます。
2. 使用する Google アカウントでログインします。
   （ここで作成したフォルダは、このアカウントのマイドライブに作られます）
3. 左上の **「新しいプロジェクト」** をクリックします。
4. 画面上部の「無題のプロジェクト」をクリックし、
   **`日本法令データベース`** など分かりやすい名前に変更します。

## 3. ソースコードの配置方法

配置方法は2通りあります。**どちらか一方**を選んでください。

### 方法A：単一ファイル版を貼る（推奨・貼り付け2回）

`dist/` に、全ソースを1つに結合した配布用ファイルを用意しています。

1. `dist/appsscript.json` を `appsscript.json` へ貼り付ける（→ 3-1・3-2）
2. `dist/日本法令データベース.gs` を `コード.gs` へ貼り付ける

これだけで完了です。手順の詳細は **[はじめかた.md](はじめかた.md)** をご覧ください。

> `dist/` は `src/` から自動生成したものです。中身は分割版とまったく同じで、
> 結合版に対してもテスト28件が通ることを確認しています。

### 方法B：分割版を貼る（開発・改修する場合）

コードを継続的に改修する場合は、責務ごとに分かれた `src/` を使うほうが扱いやすいです。
以下は方法Bの手順です。

### 3-1. マニフェストファイルを表示する

1. 左メニューの **⚙️（プロジェクトの設定）** をクリックします。
2. **「`appsscript.json` マニフェスト ファイルをエディタで表示する」**
   のチェックを **オン** にします。

### 3-2. `appsscript.json` を貼り付ける

1. 左メニューの **`<>`（エディタ）** に戻ります。
2. ファイル一覧の `appsscript.json` をクリックします。
3. 中身をすべて削除し、本リポジトリの `src/appsscript.json` の内容を貼り付けます。

5. これを以下の20ファイルすべてについて繰り返します。

## 4. 必要な権限

`appsscript.json` で要求しているのは、以下の3つだけです。

| スコープ | 用途 | なぜ必要か |
| --- | --- | --- |
| `.../auth/drive` | Google Drive | 法令フォルダとファイルの作成・更新 |
| `.../auth/script.external_request` | 外部通信 | e-Gov APIへのアクセス |
| `.../auth/script.scriptapp` | トリガー | 自動実行の設定 |

**e-Gov法令APIは認証不要**のため、APIキーやパスワードは一切使いません。
Script Properties に保存するのは Google Drive のフォルダIDと日時だけで、
認証情報は保存しません。

## 5. 初回認証

初めて関数を実行するとき、Googleの認証画面が表示されます。

1. エディタ上部の関数選択欄で **`verifyApiSpec`** を選びます。
2. **▶ 実行** をクリックします。
3. 「承認が必要です」→ **「権限を確認」** をクリックします。
4. 使用する Google アカウントを選びます。
5. **「このアプリは Google で確認されていません」** と表示されます。
   これは自作スクリプトでは正常な表示です。
   - **「詳細」** をクリック
   - **「（プロジェクト名）（安全ではないページ）に移動」** をクリック
6. 要求されている権限を確認し、**「許可」** をクリックします。

### `verifyApiSpec()` の結果の見方

実行ログ（下部の「実行ログ」）に照合レポートが出ます。

- **`結果: OK（設定と公式仕様は一致）`**
  → そのまま第6章へ進んでください。
- **`結果: 要確認`**
  → レポートの「公式仕様に存在するパス」と
  「GET ... のパラメータ」を見て、`02_api_spec.gs` の
  `ENDPOINTS` と `PARAMS` を実際の値に修正してください。
  修正が必要なのはこのファイルだけです。
- **`OpenAPI: (取得できず)`**
  → ブラウザで <https://laws.e-gov.go.jp/api/2/swagger-ui/> を開き、
  表示されるパスとパラメータ名を目視で `02_api_spec.gs` と照合してください。

## 6. `setup()` の実行方法

1. 関数選択欄で **`setup`** を選びます。
2. **▶ 実行** をクリックします。
3. 完了まで数分かかります（45件の法令を1件ずつ、間隔を空けて取得するため）。

`setup()` が行うこと：

1. マイドライブ直下に **「日本法令データベース」** フォルダを新規作成
2. サブフォルダを自動作成
3. フォルダIDを Script Properties へ保存
4. 対象法令をe-Govで検索し、正式な法令IDを特定
5. 法令本文XMLを取得
6. 原本XMLを保存
7. Markdownへ変換して保存
8. 構造化JSONを生成して保存
9. 法令一覧CSVを生成
10. 同期情報・ログを保存

### ⏱ 実行時間の上限について

Apps Script は1回の実行が **最大6分** です。45件すべての取得が
6分を超えた場合、システムは安全に中断し、ログに
「実行時間の上限に近づいたため、残りは次回に持ち越します」と記録します。

その場合は **`syncAllLaws()` を数回実行**してください。
すでに取得済みの法令はハッシュ比較で「変更なし」となりすぐ終わるため、
実行するたびに未取得の法令が進みます。

### 2回目以降の `setup()` について

`setup()` を何度実行しても、**フォルダは重複作成されません**。
保存済みのフォルダIDを再利用し、同名フォルダがあればそれを使います。

```
│   ├── 法令一覧.csv          ← 全法令の一覧（Excelで開けます）
│   ├── 同期状態.json         ← システムの台帳（触らないでください）
│   ├── 最終同期情報.json      ← 前回実行の結果
│   └── エラーログ
├── 01_税制
│   ├── 01_法律      ← 所得税法.md など
│   ├── 02_政令      ← 所得税法施行令.md など
│   ├── 03_省令      ← 所得税法施行規則.md など
│   ├── 04_その他
│   ├── 99_履歴      ← 改正前のファイル
│   └── structured   ← 条・項・号の構造化JSON
├── 02_社会保険      （同じ構成）
├── 03_労働保険      （同じ構成）
├── 04_関連法令      （同じ構成）
├── 90_RAW_XML       ← 原本XML（加工なし）
│   ├── 税制
│   ├── 社会保険
│   ├── 労働保険
│   └── 関連法令
└── 99_システムログ   ← 実行ログ
```

### 原本データと加工データの区別

| 区分 | 場所 | 内容 |
| --- | --- | --- |
| **原本** | `90_RAW_XML/` | e-Govから取得したデータそのまま（`.xml` または `.json`）。加工していません |
| **加工** | 各カテゴリの `.md` / `structured/` | 原本XMLから**機械的に変換**したもの |

条文の正確性が問題になる場面では、必ず原本XMLか
e-Gov公式サイトを確認してください。

**AIによる要約・意訳・書き換えは一切行っていません。**
Markdownへの変換は、見出しを付けるなどの構造化のみで、
条文の文字列はそのまま出力しています。

### ⚠️ 手動で変更しないでください

Drive上のフォルダ名・ファイル名を手で変更すると、自動更新が
正しく動かなくなります。中身を読むだけにしてください。

## 8. 自動更新トリガーの設定方法

1. 関数選択欄で **`installTrigger`** を選びます。
2. **▶ 実行** をクリックします。

これで **毎日午前3時台（日本時間）** に `syncLaws()` が自動実行されます。
PCの電源が入っていなくても、Googleのサーバー側で実行されます。

- 既にトリガーがある場合、**重複登録はされません**。
- 現在のトリガーは **`listTriggers()`** で確認できます。
- 実行時刻を変えたい場合は、`00_config.gs` の
  `CONFIG.TRIGGER.HOUR_OF_DAY` を変更し、
  `removeTrigger()` → `installTrigger()` の順で実行してください。

## 9. Dry Run の方法

**実際には何も書き換えずに**、何が更新される予定かだけを確認できます。

1. 関数選択欄で **`dryRunSync`** を選びます。
2. **▶ 実行** をクリックします。
3. 実行ログに、更新される予定の法令が一覧表示されます。

Dry Run では、API取得・法令の照合・更新判定・ハッシュ比較までは実行しますが、
**Google Drive上のファイルは一切書き換えません**（台帳も更新しません）。

## 10. 手動同期の方法

エディタ上部の関数選択欄から選んで実行します。

| 関数 | 内容 |
| --- | --- |
| `syncLaws()` | 通常の同期。改正された法令だけを更新 |
| `syncAllLaws()` | 全法令を強制的に確認（ハッシュ比較で更新判定） |
| `dryRunSync()` | 何も書き換えずに更新予定だけ確認 |
| `showStatus()` | 現在の状態を表示 |

### 特定の法令・カテゴリだけ同期する

引数が必要な関数は、選択欄から直接実行できません。
以下のように **呼び出し用の関数を作って実行** してください。

`18_main.gs` の末尾などに追記します。

```javascript
/** 所得税法だけを同期する */
function 所得税法だけ同期() {
  syncSingleLaw('所得税法');
}

/** 税制カテゴリだけを同期する */
function 税制だけ同期() {
  syncCategory('tax');
}
```

保存後、関数選択欄に `所得税法だけ同期` が現れるので、それを実行します。

指定できるカテゴリは次の3つです。

- `syncCategory('tax')` … 税制
- `syncCategory('social_insurance')` … 社会保険
- `syncCategory('labor_insurance')` … 労働保険
- `syncCategory('related')` … 関連法令

## 11. 法令の追加方法

**コード本体を変更する必要はありません。** `01_laws_config.gs` だけを編集します。

1. `01_laws_config.gs` を開きます。
2. `getLawsConfig()` の中の配列に、次の形式で追記します。

```javascript
{
  category: 'tax',                 // tax / social_insurance / labor_insurance / related
  name: '印紙税法',                 // e-Gov上の正式名称
  expectedLawType: 'act',          // act / cabinet_order / ministerial_ordinance
  enabled: true,                   // false にすると同期対象から外れる
  lawId: null,                     // 法令IDが分かっていれば指定（確実）
  lawNum: null,                    // 法令番号で絞り込みたい場合に指定
  aliases: [],                     // 別名・旧称
  notes: '追加した理由をここに書く'
},
```

3. 保存して `syncLaws()` を実行すると、追加した法令が取得されます。

### 法令名は必ず e-Gov の正式名称にしてください

システムは **法令名が完全一致した候補だけ** を採用します。
部分一致しかない場合や、候補が複数ある場合は、
**推測で選ばずスキップし、WARN として記録します**。

これは「名前が似ているだけの別の法令」を誤って保存しないための、
意図的な安全設計です。

正式名称は <https://laws.e-gov.go.jp/> で検索して確認してください。

### 候補が複数出てしまう場合

法令ページのURL（例：`https://laws.e-gov.go.jp/law/340AC0000000033`）の
末尾が法令IDです。これを `lawId` に指定すれば確実に特定できます。

```javascript
{
  category: 'tax',
  name: '所得税法',
  expectedLawType: 'act',
  enabled: true,
  lawId: '340AC0000000033',   // ← ここに指定すると検索せず確実に取得
  lawNum: null,
  aliases: [],
  notes: '候補が複数出たため法令IDを直接指定'
},
```

### 法令を一時的に外したい場合

**削除せず** `enabled: false` にしてください。
設定を残しておけば、あとで簡単に戻せます。

## 12. エラー時の確認方法

### 手順1：状態を確認する

関数選択欄で **`showStatus`** を実行します。
設定・フォルダ・同期状況・トリガーがまとめて表示されます。

### 手順2：ログを見る

- **実行ログ**：エディタ下部に直近の実行結果が表示されます。
- **Driveのログ**：`99_システムログ/sync_20260903_120000.log` の形式で
  実行ごとに保存されます。
- **エラーログ**：エラーが出た実行だけ、
  `00_システム情報/エラーログ/errors_(日時).json` に要約が残ります。

ログレベルの意味：

| レベル | 意味 | 対応 |
| --- | --- | --- |
| `INFO` | 正常な動作 | 対応不要 |
| `WARN` | **人間の確認が必要** | 内容を確認してください |
| `ERROR` | 1件の処理が失敗 | 他の法令の処理は継続しています |

### よくあるエラーと対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `法令が見つかりませんでした（検索結果0件）` | 法令名がe-Govの正式名称と違う | e-Govで正式名称を確認し `01_laws_config.gs` を修正 |
| `候補が◯件あり、自動で確定できません` | 同名の法令が複数ある | `lawId` に法令IDを直接指定（→第11章） |
| `法令名が完全一致する候補がありません` | 表記ゆれ | ログに出る候補名を見て `name` を修正 |
| `フォルダID "..." にアクセスできません` | フォルダを削除した／権限がない | `resetRootFolder()` → `setup()` |
| `ルートフォルダIDが設定されていません` | `setup()` 未実行 | `setup()` を実行 |
| `HTTP 429` `HTTP 503` | 一時的なアクセス集中 | 自動でリトライされます。続く場合は時間を空けて再実行 |
| `レスポンスをJSONとして解析できませんでした` | **API仕様が変わった可能性** | `verifyApiSpec()` を実行して差異を確認 |
| `法令本文XMLを取得できませんでした` | 同上 | 同上 |
| `実行時間の上限に近づいたため...` | 6分制限 | `syncAllLaws()` を数回実行（→第6章） |

**1件の法令の失敗で、全体の処理が止まることはありません。**
最後に必ず「成功件数／更新件数／変更なし件数／失敗件数」が記録されます。

## 14. 停止方法

### 自動更新だけを止める

関数選択欄で **`removeTrigger`** を実行します。
これで自動実行が止まります。Drive上のデータはそのまま残ります。

再開したいときは `installTrigger()` を実行してください。

### 一時的に特定の法令だけ止める

`01_laws_config.gs` で、その法令の `enabled` を `false` にします。

## 15. 完全に削除する場合の注意事項

**削除は元に戻せません。順番と影響を必ず確認してください。**

### 手順

1. **`removeTrigger()` を実行**
   先にトリガーを止めます。これをせずにフォルダを消すと、
   自動実行がエラーになり続けます。

2. **データを保存したい場合はバックアップを取る**
   Google Drive で「日本法令データベース」フォルダを右クリック →
   「ダウンロード」でZIPとして保存できます。
   `90_RAW_XML` の原本XMLと `99_履歴` は再取得できない
   （過去時点のデータを含む）ため、特に注意してください。

3. **Google Drive のフォルダを削除**
   「日本法令データベース」フォルダをゴミ箱へ移動し、
   ゴミ箱からも完全に削除します。

4. **Apps Script プロジェクトを削除**
   <https://script.google.com/> のプロジェクト一覧から、
   該当プロジェクトの **⋮** →「削除」を選びます。

### 注意事項

- **Driveのフォルダだけを消して、プロジェクトを残さないでください。**
  トリガーが動き続け、`setup()` 未実行の状態でエラーになります。
  フォルダを消す場合は、必ず先に `removeTrigger()` を実行してください。

- **フォルダを消してプロジェクトを残したい場合**は、
  `removeTrigger()` → `resetRootFolder()` を実行してください。
  次回 `setup()` でフォルダが作り直されます。

- **Script Properties だけを消しても、Drive上のデータは消えません。**
  フォルダIDを見失うだけで、`setup()` を実行すれば
  マイドライブ上の同名フォルダが再利用されます（データは失われません）。

## 開発者向け情報

### ローカルでのテスト実行

Google Apps Script の各サービスをNode.js上で再現するスタブを用意しているため、
**`src/*.gs` を書き換えることなく** そのままローカルで実行・検証できます。

```bash
cd japan-law-db/tools
node run-tests.js          # テストスイート（28件）
node e2e-setup.js          # setup() の通し実行とフォルダ構成の確認
node build-single-file.js  # dist/ の単一ファイル版を再生成
node verify-bundle.js      # 生成した単一ファイル版に対してテストを実行
```

`src/` を編集したら、`build-single-file.js` で `dist/` を再生成してください。
`verify-bundle.js` は、結合版が分割版と同じ動作をすることを検証します。

e-Gov APIへは接続せず、スタブ応答で実行されるため、公的APIに負荷をかけません。

### GAS上でのテスト実行

関数選択欄で **`runAllTests`** を実行します。
テスト用のフォルダを作って検証し、終了時に片付けます
（本番データには触れません）。

### ファイル構成の考え方

| 層 | ファイル | 責務 |
| --- | --- | --- |
| 設定 | `00_config` `01_laws_config` `02_api_spec` | 値だけを持つ。処理を書かない |
| 基盤 | `03_utils` `04_logger` `05_properties_service` `06_http_client` | 汎用処理 |
| API | `07_egov_api` `08_response_reader` | e-Govとの通信。保存処理は持たない |
| 変換 | `09_xml_parser` `10_markdown_converter` `11_structured_json` `12_hash_service` | 純粋関数。外部サービスに依存しない |
| 保存 | `13_drive_service` `14_catalog_service` | Drive操作。API処理は持たない |
| 業務 | `15_law_service` `16_sync_service` `17_trigger_service` | 業務ロジック |
| 入口 | `18_main` | 利用者が実行する関数のみ |

XMLパーサは `XmlService` に依存せず、依存関係のない純粋なJavaScriptで
実装しています。これにより、GAS上とローカルで**まったく同じコード**が動き、
変換ロジックを実際に検証できます。
