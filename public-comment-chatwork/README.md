# パブリックコメント → ChatWork 通知システム

e-Gov パブリックコメントの新着案件を監視し、キーワードで絞り込んで
ChatWork へ通知する Google Apps Script システム。

`japan-law-db`（法令データベース）とは**別プロジェクト**です。
法令本文と、意見募集案件は性質が異なるため、意図的に分離しています。

## 調査済みの事実

実装を始める前に確認した内容です。**推測ではありません。**

### ChatWork API（確定）

稼働中の公開クライアント実装（npm: `@peakys/chatwork-api`, `chatwork-api-wrap`）の
ソースコードを照合して確認しました。

| 項目 | 値 |
|---|---|
| 投稿先 | `POST https://api.chatwork.com/v2/rooms/{room_id}/messages` |
| 認証ヘッダ | `X-ChatWorkToken` |
| Content-Type | `application/x-www-form-urlencoded` |
| 本文パラメータ | `body` |
| 疎通確認用 | `GET /me`（トークン確認）、`GET /rooms`（ルームID確認） |

### e-Gov パブリックコメント（一部未確認）

- RSS配信が提供されていることは確認済み
- **フィードの正確なURLは未確認**（開発環境から到達できないため）

そのため `01_sources.gs` では、URLを決め打ちせず次の順に試す設計にしています。

1. 前回発見に成功したURL（Script Properties に保存）
2. 候補URLの直接試行
3. **案内ページ内のリンクからフィードURLを自動発見**

3があるため、候補が全滅しても自力で見つけられます。

## 設計上の方針

### 二重投稿を絶対に避ける

この種の通知で最も多い事故は「同じ案件を何度も投稿する」ことです。
通知済みの案件IDを台帳に記録し、ハッシュで差分を判定します。

### 投稿は段階的に解禁する

投稿は取り消せない外向きの操作のため、既定では**投稿しません**。

1. `dryRun`（ログに出すだけ）
2. テスト用ルームへ投稿
3. Script Properties の `POSTING_ENABLED` を `true` にして本番解禁

### 初回実行で大量投稿しない

`NOTIFY.NOTIFY_ON_FIRST_RUN` が `false` のとき、初回は既存案件を
「通知済み」として記録するだけで投稿しません。

### 認証情報をコードに書かない

ChatWork APIトークンは Script Properties にのみ保存します。
ソースコードにも、このリポジトリにも書きません。

> 法令データベースは e-Gov が認証不要なため、認証情報を一切持ちませんでした。
> 本システムは**トークンを扱う点が異なります**。漏れると、そのアカウントとして
> 発言できてしまうため、取り扱いには注意してください。
